# ビジュアル思考（Senior PdM向け）

## 目的
言葉と論理だけで考えると、関係を一つずつ頭に抱えながら進むことになり、遅くなる。
ビジュアルにすると、大小・位置・つながり・欠けている部分が一度に見え、違和感から次の問いが生まれる。
このskillは、**現時点の整理を1枚で見せる**ことで、仮説を深める速度を上げる。

グラフは選択肢の一つにすぎない。定性的な論点は、マトリクス、構造図、関係図、タイムラインなどで表す。

## 使う場面
- 戦略仮説を立てた直後に、全体像を1枚にしたいとき
- `strategy-pattern-recognition` で照合したパターンを、シグネチャー図で確かめたいとき
- 議論が言葉だけで空回りしているとき（論点が多い、関係が複雑、人によって前提が違う）
- 上申や合意形成の前に、現状の理解を揃えたいとき

## 原則
1. **軸や枠組みを選ぶこと自体が仮説である。** 何を縦横に置くか、何を箱にして何を矢印にするかで、見える構造が変わる。
2. **描く前に、期待する形を言う。** 「仮説Aが正しければこう見える、Bならこう見える」を先に示してから描く。
3. **確定と仮説と不明を描き分ける。** 確認済みの事実は実線、仮説は点線、不明は「？」や空白の枠にする。空白は次に調べることのリストになる。
4. **1枚1メッセージ。** タイトルは「〇〇の図」ではなく、図から言える結論を一文で書く（例：「AI利用が深い顧客ほどシートが減っている」）。
5. **スナップショットとして扱う。** 日付と版を入れる。情報が増えたら描き直す前提で、完成度より速さを優先する。

## 手順

1. **問いと読み手を決める**
   この1枚で何を明らかにしたいかを一文にする。自分の思考用か、チームとの合意用か、上申用かを決める。

2. **素材の種類を見分ける**
   手元の情報が次のどれにあたるかを分ける。
   - 量（数字の大小・推移・分布）
   - 位置（比較対象の中での立ち位置）
   - 構造（レイヤー、分解、階層）
   - 関係・流れ（お金、データ、価値、因果のつながり）
   - 時間（順序、変化、移行）

3. **表現の型を選ぶ**
   `references/visual-types.md` から、素材と問いに合う型を1〜2個選ぶ。候補が複数あれば、それぞれ何が見えるかを一行で添えて提案する。

4. **期待する形を先に述べる**
   仮説ごとに「こう見えるはず」を書く。データがない段階では、これ自体を手描き風の想定図として描いてもよい。

5. **描く**
   使える環境で、最も見やすい手段を選ぶ（下の「描画手段」）。

6. **読み解く**
   期待した形と比べて、合っている点、ずれている点、外れ値、空白を挙げる。ずれと空白を「次の問い」に変換する。

7. **更新する**
   新しい情報が入ったら同じ図を更新し、版を上げる。前の版との差分が議論の進捗になる。

## 描画手段（使える順に）
1. アーティファクトやインラインのビジュアル表示が使える環境では、HTML／SVGで描く。共有や再訪が見込まれるならアーティファクトにする。
2. データがあり、コードを実行できる環境では、実データでグラフを描く。
3. 上記が使えなければ、Mermaid（構造図・フロー・タイムライン）や表で描く。
4. 最後の手段として、テキストの図（ASCII）で描く。

## 出力フォーマット

```
## 問い
（この1枚で明らかにしたいこと）

## 選んだ表現と理由
- 型：...（なぜこの型か、何が見えるか）

## 期待する形
- 仮説Aなら：...
- 仮説Bなら：...

## 図
（ビジュアル本体。タイトルは結論の一文。日付と版を入れる）

## 読み解き
- 期待どおりの点：...
- ずれ・外れ値：...
- 空白（未確認）：...

## 次の問い
- ...
```

## 守ること
- 飾らない。色や装飾は意味の違いを示すときだけ使う。
- 凡例を必ず入れる（実線・点線・？の意味、色の意味）。
- 実データがない部分を、データがあるかのように描かない。想定図であることを明記する。
- 要素を詰め込みすぎない。1枚で伝わらなければ、問いを分けて2枚にする。
