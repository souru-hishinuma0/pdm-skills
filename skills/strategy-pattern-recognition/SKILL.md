# 戦略パターン認識（Senior PdM向け）

## 目的
戦略業務で、ゼロから論理を積み上げる前に「この症状はどの型か」で初期仮説を素早く立てる。
パターンは結論ではなく仮説の供給源。必ず反証の観点とセットで使う。

考え方の土台：勝てる戦略 ＝ 定石（このパターン集）＋ インサイト（定石から外れる独自の視点）。

## 使う場面
- 事業・プロダクト戦略の立案や見直し
- 競合の動き、市場変化への対応方針を考えるとき
- 価格・パッケージ戦略、投資判断（作る／買う／撤退する）
- 戦略ドキュメントや上申資料のレビュー（論点の抜け漏れチェック）

個別アジェンダのPRD作成や施策の検証サイクルには使わない（通常の仮説検証プロセスで回す）。

## パターン集
領域ごとにファイルを分けている。照合の前に、該当するファイルを読む。

| ファイル | 内容 |
|---|---|
| `references/common.md` | 領域横断（A1〜A6） |
| `references/b2b-saas.md` | B2B SaaS（B1〜B6） |
| `references/ai-product.md` | AIプロダクト（C1〜C6） |
| `references/_template.md` | パターン追加用のテンプレートとルール |

`common.md` は常に読む。それに加えて、テーマの領域に応じたファイルを読む。

## 手順

1. **症状を言語化する**
   起きている事象を、解釈を混ぜずに箇条書きにする。数字があれば数字で書く。情報が足りなければ、照合に必要な事実を2〜3個だけユーザーに確認する。

2. **領域を判定する**
   B2B SaaS／AIプロダクト／両方 を決め、対応する references を読む。

3. **パターンを照合する**
   症状シグナルが合うパターンを2〜3個挙げる。1つに絞らない。それぞれ確信度（高・中・低）と、合致している症状・合致していない症状を明示する。

4. **検証を設計する**
   各候補について「確認データ」と「反証シグナル」を示す。どのデータを最初に見れば候補を最も早く絞れるかを指定する。
   各カードの「シグネチャー図」を使い、仮説どおりならどんな形に見えるかを示す。実際に描く場合は `visual-thinking` skill の手順に従う。

5. **定石を示す**
   最も有力な候補について、定石の打ち手と落とし穴を出す。パターン同士の連鎖（例：B2 → A2）があれば指摘する。

6. **＋αを考える**
   「この定石を競合も同じように打つとしたら、どこで差がつくか」「あえて定石から外れるならどこか」を1〜2個問う。答えは出し切らなくてよく、問いとして残してよい。

7. **該当なしの扱い**
   どのパターンにも合わない場合は無理に当てはめず「該当なし」と明言する。そのうえで、今回の事例を新パターン候補として `references/_template.md` の形式で書き起こすことを提案する。

## 出力フォーマット

```
## 症状の整理
- ...

## 照合結果
| 候補パターン | 確信度 | 合致する症状 | 合致しない症状 |

## 検証の設計
- 最初に見るべきデータ：...
- 候補ごとの確認データと反証シグナル

## 有力仮説での定石
- 打ち手：...
- 落とし穴：...

## ＋αの問い
- ...
```

## 守ること
- パターン名を出すだけで終えない。必ず反証シグナルまで書く。
- 症状に合わない部分を無視しない。合わない事実こそ明記する。
- AI領域のパターンは技術とコスト構造の変化が速い。前提（モデル性能、推論コスト、競合の状況）が今も成り立つかを確認してから使う。
